# AI FIGHTER — 2D 対戦格闘ゲーム

ブラウザで動く 2D 対戦格闘ゲームです。TypeScript と Canvas だけで作ってあり、
画像ファイルも音声ファイルも 1 つも使っていません（キャラクターはその場で
骨格を組んで描き、音は Web Audio で合成しています）。

前作 [kakuge-](https://github.com/basashi-834/kakuge-)（C++17 + SDL2）の設計思想
——フレーム単位の技データ、硬直差をデータに直接書く方式、3 種類の当たり判定の
分離——を引き継ぎ、**すぐ遊べる**形に作り直したものです。

```
npm install
npm run dev      # http://127.0.0.1:5173/ で起動
npm test         # 96 件のテスト（フレームデータの実測検証を含む）
npm run build    # dist/ に出力
```

## 遊びかた

| | 操作 |
|---|---|
| 移動 | `A` / `D`（1P）、`←` `→`（2P） |
| しゃがみ | `S`（1P）、`↓`（2P） |
| ガード | 後ろを入れる（下段は しゃがみガード、ジャンプ攻撃は 立ちガード） |
| ジャンプ | `W`（1P）、`↑`（2P） |
| パンチ | `U` 弱 / `I` 中 / `O` 強 |
| キック | `J` 弱 / `K` 中 / `L` 強 |
| 投げ | 弱P + 弱K（近距離） / 投げ抜けも同じ入力 |
| ダッシュ | 前・前 ／ バックダッシュ 後ろ・後ろ（ダッシュ中は技でキャンセルできる） |
| 必殺技 | `236`＋P（波動拳）、`623`＋P（昇龍拳）、`214`＋K など |
| ため技 | 後ろに 45F ためてから前＋ボタン／下にためてから上＋ボタン（黒羽） |
| EX 必殺技 | 同じコマンド + ボタン 2 つ同時（ゲージ 0.5 本） |
| 超必殺技 | `236236`＋P など（ゲージ 1 本） |
| ポーズ | `Esc` |
| 当たり判定の表示 | `F1`（トレーニング中） |
| 技表 | タイトル、またはポーズメニューから |

USB ゲームパッドにも対応しています（スティック / 十字キーで移動、
`X`/`Y`/`RB` がパンチ、`A`/`B`/`RT` がキック、`LB` が投げ）。

## モード

| | 内容 |
|---|---|
| アーケード | ロスター全員を順に倒していく。勝ち進むほど CPU が強くなる |
| CPU と 1 戦 | 好きな相手と 1 試合 |
| 2 人対戦 | 1 台のキーボードで対戦（1P は WASD + UIOJKL、2P は矢印 + TYUGHJ） |
| トレーニング | 相手の行動を固定して練習。当たり判定・フレーム表示・入力表示つき |
| オンライン対戦 | ロールバック方式。サーバ不要の直接接続 |
| 技表 | 全キャラの全技のフレームデータ |

## 中身の話

### フレームの数えかた

技は 1F 目から始まり、全体フレーム `T = (発生 - 1) + 持続 + 硬直` まで続きます。

```
発生 4F / 持続 3F / 硬直 7F の技
  1-3F    発生前
  4-6F    攻撃判定が出ている   ← 「発生 4F」とはここのこと
  7-13F   硬直
  14F     行動可能
  全体 = (4-1) + 3 + 7 = 13F
```

### 硬直差はデータに直接書く

多くの実装では「持続」「硬直」「のけぞり」を別々に書き、硬直差は
そこから計算した結果として出てきます。この方式だと、技を調整するたびに
「表に書いてある硬直差」と「実際の挙動」がずれていきます。

そこでこのゲームでは逆にしています。**硬直差をデータに書き、
のけぞり時間をそこから逆算します。**

```
のけぞり = 硬直差 + (全体 - 発生) + 1
```

この式が本当に正しいかは、[tests/frames.test.ts](tests/frames.test.ts) で
実際に試合を回して 1 フレーム単位で数えて確かめています。

そのおかげで、次の 2 つがデータを見るだけで分かります。

- **コンボになる** … 前の技のヒット時硬直差 ≧ 次の技の発生
- **確定反撃になる** … ガード時硬直差の絶対値 ≧ 相手の技の発生

### 当たり判定

攻撃判定・食らい判定・押し合い判定を厳密に分けています。
食らい判定は姿勢ごとに頭・胴・脚の 3 つに分かれ、
さらに **技ごと／フレームごとに差し替え**できます。

```
優先順位（上が強い）
  1. frameBoxes の hurtboxes … そのフレームだけ差し替え
  2. 技の hurtboxes           … その技の間ずっと差し替え
  3. 姿勢ごとの標準           … 技を出していないときの形
```

足払いで前へ伸ばした脚がそのまま「殴られる場所」になるので、
伸びた脚を狙って潰す、という差し合いが成立します。

### 小数を一切使わない

内部の座標はすべて整数です（1 ピクセル = 256 単位のサブピクセル）。
小数を使うと、機種やブラウザによって計算結果が最下位ビットでずれることがあり、
それはそのまま「オンライン対戦でだけ試合がずれる」という、
いちばん見つけにくい不具合になります。

乱数も時刻も使いません。**同じ状態 + 同じ入力 → 必ず同じ結果**です。
これは [tests/sim.test.ts](tests/sim.test.ts) で常に検証しています。

### オンライン対戦（ロールバック方式）

相手の入力が届くのを待つと、その待ち時間だけ操作が遅れます。
格闘ゲームではこれが致命的なので、次のようにしています。

1. 相手の入力がまだ来ていないフレームは「たぶん前と同じ入力だろう」と
   決めつけて先に進む
2. あとで本当の入力が届いて予想と違っていたら、そのフレームまで**巻き戻して**
   正しい入力でやり直す

自分の操作は常に遅れなく反応し、ずれたときだけ画面が少し飛びます。
これが成り立つのは、上に書いた決定性のおかげです。

「遅延ありでロールバックした結果」と「最初から全部の入力が分かっていた場合」が
**完全に一致する**ことも、テストで確かめています。

接続はサーバを使わない WebRTC の直接接続です。片方が作った招待コードを
相手に渡し、返事コードを戻すとつながります（メッセージアプリなどで
文字列を 2 回やり取りするだけです）。

### CPU 対戦相手

**人間とまったく同じ入力しか行いません。** 体力を直接いじったり、
コマンドを飛ばして技を出したりはしません。波動拳を撃ちたいときは、
`2` `2` `3` `3` `6` `6+P` と 1 フレームずつ実際に入力します。

強さは 4 段階で、次の要素を変えています。

| | 反応 | 攻めの頻度 | ガード | 対空 | コンボ完走 |
|---|---|---|---|---|---|
| やさしい | 24F | 30 | 35% | 15% | 25% |
| ふつう | 16F | 50 | 62% | 45% | 60% |
| つよい | 10F | 70 | 84% | 75% | 85% |
| 鬼 | 5F | 84 | 96% | 94% | 97% |

「反応」は、何フレーム前の状況を見て判断するか、です。
人間と同じで、見てから動くには時間がかかる、という形で弱さを作っています
（判断そのものを間違えさせるより、こちらのほうが自然に弱くなります）。

やることは、間合いに応じた技選び（**届く技しか振らない**）、対空、
空振りへの確定反撃、当てた技の必殺技キャンセル、飛び道具での牽制、
起き上がりの無敵技です。

ため技キャラを操作するときは、その場でためはじめると 48 フレーム棒立ちに
なってしまうので、**待っているあいだにためておく**ようにしています。
人間のため技キャラの動きと同じです。

強さがちゃんと段階になっていることは
[tests/ai.test.ts](tests/ai.test.ts) で何十試合も回して確かめています
（鬼 CPU は「近づいて中攻撃を連打するだけ」の相手に 10 戦 8 勝以上、
やさしい CPU は勝ちすぎない、など）。

### 絵と音

画像ファイルは 1 枚も使っていません。腰・胴・頭・両腕・両脚を
角度で組み立てて、その場で描いています。技ごとに「ためる / 当てる / 戻す」の
3 つのポーズを持っていて、その間を補間します。

音も同じで、Web Audio でその場で合成しています
（打撃は短いノイズ + 低い音、ガードは高い金属音、というように波形で作り分け）。

## ディレクトリ

```
src/
  engine/     試合のシミュレーション（描画のことを一切知らない）
    constants.ts  座標系や画面の大きさ
    types.ts      技データ・キャラクターデータの型
    input.ts      入力とコマンド認識
    fighter.ts    ファイター 1 人ぶんの状態
    match.ts      1 フレーム進める処理（中心）
  data/       キャラクターと技のデータ
  ai/         CPU 対戦相手
  render/     描画（骨格・エフェクト・背景・画面表示）
  net/        オンライン対戦（ロールバックと WebRTC）
  game/       画面遷移とメインループ
  audio/      効果音と音楽の合成
tests/        96 件のテスト
docs/         中身のしくみの解説
```

詳しい流れは [docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md) にまとめてあります。
「ボタンを押してから相手の体力が減るまで」に何が起きているかを、
順番どおりに追いかけた解説です。
