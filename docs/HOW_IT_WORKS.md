# 中身のしくみ

「ボタンを押してから相手の体力が減るまで」に何が起きているかを、
順番どおりに追いかけます。コードを読む前にここを読むと、
どのファイルを開けばいいかが分かります。

---

## 全体の形

```
        キーボード / パッド            相手（CPU または通信相手）
              │                              │
              ▼                              ▼
        game/controls.ts                ai/cpu.ts / net/rollback.ts
              │                              │
              └──────────┬───────────────────┘
                         ▼
                 engine/match.ts  ← ここだけが「試合の真実」
                         │
                 （出来事のリスト）
                         ▼
              render/ と audio/  ← 見せる／鳴らすだけ
```

大事なのは、**engine/ が描画のことを一切知らない**ことです。
engine/ の中には `CanvasRenderingContext2D` も `window` も出てきません。
そのおかげで、engine/ はブラウザ無しのテストでそのまま動かせますし、
巻き戻して何度もやり直しても、演出が二重に出ることがありません。

---

## 1 フレームの流れ

`game/app.ts` のメインループは、**必ず 1/60 秒きざみ**で `stepMatch` を呼びます。
画面の書き換え速度（60Hz とは限らない）に合わせてしまうと、
144Hz のパソコンでは技の発生が速くなり、フレームデータが意味を失うためです。

`engine/match.ts` の `stepMatch` は、次の順に処理します。

1. **入力を履歴に積む**（`engine/input.ts`）
   1 フレームぶんの入力を 16 ビットの整数 1 個で持ちます。
   オンラインで送る量が小さく、比較も `===` 1 回で済みます。
2. **各ファイターを進める**（`updateFighter`）
   - ヒットストップ中なら何も進めない（入力の記録だけは進む）
   - 状態の遷移（のけぞり → 立ち、ダウン → 起き上がり、など）
   - 入力の処理（技を出す・歩く・跳ぶ・ダッシュ）
   - 重力と座標の更新
3. **壁で止める**（`clampToStage`）
4. **押し合いを解決する**（`resolvePush`）
   画面端では、端にいる側は動かず、相手だけが押し戻されます。
5. **攻撃判定を見る**（`resolveStrikes`）
6. **飛び道具を進める**（`updateProjectiles`）相殺もここ
7. **離れすぎを直す**（`enforceSeparation`）
   2 人の距離の上限を 404px に決めてあるので、
   どちらかが画面の外に取り残されることがありません。
8. **カメラ・制限時間・ラウンド判定**

## ボタンを押してから技が出るまで

### 1. バッファ

`engine/input.ts` は、ボタンごとに「最後に押されたフレーム」と
「すでに技として使ったフレーム」を覚えています。

```
押した記録 > 使った記録 かつ 押してから 10 フレーム以内 → まだ使える
```

これがあるので、硬直が明ける少し前にボタンを押しても、
明けた瞬間にちゃんと技が出ます。

### 2. コマンドの認識

`matchMotion` は、入力履歴を新しいほうから古いほうへたどって、
必要な方向が順番どおりに出てきているかを見ます。
あいだに関係ない方向が挟まっていても、全体が猶予フレーム以内なら成立します。

ここで気をつけているのが、**同じ方向を押しっぱなしにしている間は
1 回の入力として数える**ことです。

これをしないと、236 の「3」を 2 フレーム押しただけで
3 が 2 回ぶんに数えられ、236236（超必殺技）まで成立してしまいます。
実際に遊ぶと必ず数フレームは押しっぱなしになるので、
ここを分けないと波動拳のたびに超必殺技が暴発します。
（[tests/input.test.ts](../tests/input.test.ts) に、この暴発を防ぐテストがあります）

### 3. どの技を出すか

`tryMoves` は、**コマンドが長い技・ゲージを使う技から先に**調べます。
同じ 236 でも、超必殺技 → EX 必殺技 → 通常の必殺技、の順です。

技を出せる条件は次の 3 つです。

- 姿勢が合っている（しゃがみ技はしゃがんでいるときだけ）
- 行動可能、または**キャンセルできる状態**
- ゲージが足りている

### 4. キャンセル

技を出している最中でも、その技の `cancels` に書いてある条件を満たせば、
残りの持続・硬直を打ち切って次の技の 1F 目へ移れます。

| 種類 | 内容 |
|---|---|
| `special` | 通常技 → 必殺技 |
| `super` | 通常技 → 超必殺技 |
| `target` | 弱攻撃 → 弱攻撃（チェーンコンボ） |

それぞれ「有効な時間帯」「ヒット時 / ガード時 / 空振り時に効くか」を
別々に持っています。

## 攻撃が当たってから体力が減るまで

`resolveStrikes` が、攻撃側の攻撃判定と守備側の食らい判定の重なりを調べます。

### ガードできているか

```
・後ろを入れている
・空中ではない（空中ガードなし）
・のけぞり中・ダウン中・技の最中ではない
・ガードの高さが合っている
    中段（ジャンプ攻撃）… しゃがみガードでは防げない
    下段（足払いなど）  … 立ちガードでは防げない
```

### アーマー

剛山の突進技のように「1 発だけ耐えて突っ込む」技があります。
アーマーで受けた場合は、のけぞらずにダメージだけ受けます（威力は 55%）。

### カウンターヒット

相手が技を出し始めている最中（発生前 or 持続中）に当てると
カウンターヒットになり、ダメージ 1.2 倍・のけぞり延長になります。

### のけぞり時間

```
のけぞり = 硬直差 + (全体 - 発生) + 1
```

技を出したフレームちょうどで当てると、データに書いたとおりの硬直差になります。
持続の後ろのほうを当てる（＝重ねる）ほど、自動的に有利になります。
攻撃側の残り硬直が減るぶん、そのまま有利フレームに変わるからです。

### ヒットストップ

当てた側と喰らった側の両方が、同じフレーム数だけ完全に止まります。
座標もアニメーションもタイマーも止まりますが、**入力の記録だけは進みます**。
止まっている間に入れた必殺技コマンドが、解けた瞬間にキャンセルとして
成立するのは、このためです。

同時に掛かって同時に解けるので、ストップの長さは硬直差に影響しません。

### ダメージ補正

コンボが伸びるほどダメージが減ります（100% → 100% → 80% → 70% → …）。
ただし多段技の 2 発目以降は段数を進めません。
そうしないと 9 段の超必殺技が、補正で最後はほとんど減らなくなってしまいます。

## ロールバック（オンライン対戦）

`net/rollback.ts` がやっていることは、次の 3 つだけです。

1. 毎フレーム、**進める直前の状態をまるごと控える**
2. 相手の入力が来ていないフレームは、**直前に確定している入力と同じ**だと
   決めつけて進める
3. あとで本当の入力が届いて予想と違っていたら、そのフレームまで巻き戻し、
   正しい入力で今のフレームまで一気にやり直す

やり直しは 1 フレームのうちに終わるので、遊んでいる側からは
「たまに相手の位置が少し飛ぶ」だけに見えます。自分の操作は常に即座に反応します。

これが破綻なく動くのは、シミュレーションが完全に決定論的だからです。
`engine/` の中で小数・乱数・時刻を使っていないのは、このためです。

演出の二重発生は、`render/renderer.ts` が
「すでに見たフレーム番号以下は無視する」ことで防いでいます。

## CPU

`ai/cpu.ts` は、毎フレーム「1 フレームぶんの入力ビット」を返すだけの関数です。
`stepMatch` から見れば、人間のプレイヤーと区別がつきません。

必殺技を出したいときは、`motionSequence` でコマンドを
1 フレームずつの方向入力に展開し、順番に返していきます。

```
236 → [下, 下, 下前, 下前, 前, 前+ボタン, 前+ボタン]
```

判断の順番は次のとおりです。

1. 予約した入力が残っていれば、それを出す（コマンド入力の途中）
2. のけぞり中 → ガードを入れ続ける
3. 起き上がり → 一定確率で無敵技
4. 相手が跳んでいる → 対空
5. 相手の攻撃が届く → ガード
6. 自分の技が当たった → 必殺技でキャンセル
7. 相手が空振って硬直している → その硬直に間に合う中でいちばん強い技
8. それ以外 → 作戦（近づく / 下がる / 攻める / 飛び道具）に従う

4 と 5 では、**数フレーム前の状況**を見ています。
人間と同じで、見てから動くには時間がかかる、という形にすることで、
判断そのものを間違えさせずに自然な弱さを作っています。

攻めるときは、**届く技しか振りません**。届かない技を振ると、
そのまま硬直を晒して反撃をもらうからです。上級者がやっていることも、
突き詰めればこれです。

## 絵

`render/pose.ts` に、腰・胴・頭・両腕・両脚の角度をまとめたポーズが
30 種類以上並んでいます。角度は「真下を 0 度、前へ回す向きを +」で数えます。

```
  0 度 = 真下        90 度 = 前へ水平
180 度 = 真上       -90 度 = 後ろへ水平
```

技のポーズは 3 つで 1 組です。

```
ため（wind） → 当てる（strike） → 戻す（rec）
```

`render/fighterArt.ts` は、技の今のフレームがどの区間にあるかを見て、
この 3 つの間を補間します。発生の前半はゆっくりため、後半で一気に伸ばす、
という曲線を使っているので、同じフレーム数でも「速そうに」見えます。

奥側の手足は暗い色で先に描き、そのあと胴 → 頭 → 手前の手足、の順に重ねます。
外側には一段暗い縁取りを入れています。背景に溶けないようにするためです。
