# 2D 対戦格闘ゲーム 制作プロンプト

> このファイルは、AI FIGHTER と同じものをゼロから作らせるための「依頼文」です。
> そのままコピーして AI に渡せば動くように、要件・数値・ハマりどころまで書いてあります。
> 後半の「落とし穴集」は、実際に作って踏み抜いたものだけを載せています。

---

## 依頼

ブラウザで動く 2D 対戦格闘ゲームを作ってください。
**画像ファイルと音声ファイルは 1 つも使わないでください。**
キャラクターは骨格を組んでその場で描き、音は Web Audio で合成します。
そうすることで素材の用意を待たずに、技を足した瞬間から遊べる状態を保ちます。

## 1. 技術構成

| 項目 | 内容 |
|---|---|
| 言語 | TypeScript（`strict: true`、`noUnusedLocals`、`noImplicitOverride`） |
| 描画 | Canvas 2D のみ。WebGL もゲームエンジンも使わない |
| ビルド | Vite |
| テスト | Vitest |
| 外部ライブラリ | **ゼロ**（devDependencies だけ） |
| 内部解像度 | 480 × 270 px。整数倍に拡大して表示（`image-rendering: pixelated`） |
| フレームレート | 60fps 固定タイムステップ |

コメントは日本語で、**「なぜそうしたか」**を書いてください。
「何をしているか」はコードを読めば分かります。
そのぶん、あとから読む人が同じ判断をやり直さずに済みます。

## 2. アーキテクチャの絶対条件

### 2-1. シミュレーションは完全に決定論的にする

`src/engine/` の中では次を**一切使わないでください**。

- 小数（`float`）
- `Math.random()`
- `Date` / `performance.now()`
- `CanvasRenderingContext2D`、`window`、`document`

座標はすべて整数で持ちます。**1 ピクセル = 256 サブピクセル**とし、
ピクセルへ落とすときは常に `>> 8`（負数でも floor になる算術シフト）で統一します。

> **なぜ**：小数を使うと機種やブラウザで計算結果が最下位ビットずれることがあり、
> それは「オンライン対戦のときだけ試合がずれる」という、最も見つけにくい不具合になります。
> ロールバック方式のネットコードは、この決定論の上にしか成り立ちません。

### 2-2. engine と描画を分離する

```
入力 → engine/match.ts（試合の真実） → 出来事のリスト（SimEvent[]）
                                          ↓
                                    render / audio（見せる・鳴らすだけ）
```

engine は「このフレームに何が起きたか」をイベント配列で返すだけにし、
火花を出す・画面を揺らす・音を鳴らすのは受け取った側の仕事にします。

> **なぜ**：巻き戻して同じフレームをやり直したときに、演出だけが二重に出るのを防げます。
> また engine がブラウザに依存しないので、テストでそのまま動かせます。

### 2-3. 状態はすべて 1 つの構造体に入れる

`MatchState` の外に隠れた変数を持たないでください。
状態をまるごと複製して差し替えるだけで巻き戻しが成立する形にします。

## 3. フレームの数え方（最重要）

技は 1F 目から始まり、全体フレーム `T = (発生 - 1) + 持続 + 硬直` まで続きます。

```
発生 4F / 持続 3F / 硬直 7F の技
  1-3F    発生前
  4-6F    攻撃判定が出ている   ← 「発生 4F」とはここのこと
  7-13F   硬直
  14F     行動可能
  全体 = (4-1) + 3 + 7 = 13F
```

### 硬直差はデータに直接書く

多くの実装では持続・硬直・のけぞりを別々に書き、硬直差は結果として出てきます。
この方式だと、技を調整するたびに「表に書いた硬直差」と「実際の挙動」がずれます。

**逆にしてください。硬直差をデータに書き、のけぞり時間をそこから逆算します。**

```
のけぞり = 硬直差 + (全体 - 発生) + 1
```

導出：
```
攻撃側が動けるようになる = ヒットしたフレーム + (全体 - 発生 + 1)
守備側が動けるようになる = ヒットしたフレーム + のけぞり
硬直差 = 守備側 - 攻撃側
```

この式が正しいことは、**実際に試合を回して 1 フレーム単位で数えるテスト**で
確かめてください（式を見比べるだけでは合っているか分かりません）。

この方式にすると、データを見るだけで次の 2 つが分かります。

- **コンボになる** … 前の技のヒット時硬直差 ≧ 次の技の発生
- **確定反撃になる** … ガード時硬直差の絶対値 ≧ 相手の技の発生

## 4. 当たり判定

3 種類を厳密に分けてください。

| 判定 | 役割 |
|---|---|
| 攻撃判定（hitbox） | 相手を殴る範囲 |
| 食らい判定（hurtbox） | 殴られる範囲。頭・胴・脚の 3 つに分ける |
| 押し合い判定（pushbox） | 体どうしが重ならないようにする |

食らい判定は**技ごと・フレームごとに差し替え可能**にします。

```
優先順位（上が強い）
  1. そのフレームだけの差し替え
  2. その技のあいだずっとの差し替え
  3. 姿勢ごとの標準（技を出していないとき）
```

> **なぜ**：足払いで前に伸ばした脚が、そのまま「殴られる場所」になります。
> 伸びた脚を狙って潰す、という差し合いはこれが無いと成立しません。

矩形はローカル座標で `{x, y, w, h}`（前方が +x、足元が y=0 で上が +y）とし、
向きに応じて左右反転します。

## 5. 戦闘システムの要件

- 立ち / しゃがみ / ジャンプ（前・垂直・後ろ）
- 歩き（前後で速度が違う）、ダッシュ、バックダッシュ（**バックダッシュは前ダッシュと独立した設定にする**）
- ガード：上段（立ちのみ防御可）/ 下段（しゃがみのみ）/ 中（どちらでも）/ ガード不能
- **空中ガードは無し**
- のけぞり、ガード硬直、ダウン、起き上がり（下を入れると少し早く起きる＝受け身）
- ヒットストップ／ガードストップ：技ごとに別々の値。当てた側と喰らった側に同時にかかり同時に解ける。
  **止まっているあいだも入力の記録だけは進める**（ストップ中に入れたコマンドが解けた瞬間に成立する）
- キャンセル（種類ごとに独立した設定を持つ）
  - `special`（通常技 → 必殺技）
  - `super`（通常技 → 超必殺技）
  - `target`（弱攻撃 → 弱攻撃のチェーン）
  - それぞれ「有効な時間帯 / ヒット時 / ガード時 / 空振り時」を個別に設定
- カウンターヒット（相手の発生中・持続中に当てるとダメージ 1.2 倍・のけぞり延長）
- スーパーアーマー（決めた回数だけのけぞらずに耐える。ダメージは軽減）
- 無敵（全身 / 打撃のみ / 投げのみ / 飛び道具のみ を時間指定で）
- 投げ（距離判定・投げ抜け・コマンド投げは投げ抜け不可）
- 飛び道具（同時に出せる数の上限、弾どうしの相殺、相殺の強さ）
- 超必殺技ゲージ 3 本、EX 必殺技 0.5 本、超必殺技 1 本
- 超必殺技の暗転（相手だけ止まる）
- スタン（気絶）
- 押し合いの解決（**画面端では端にいる側が動かず、相手だけが押し戻される**）
- 2 人が離れられる距離の上限を設ける（＝どちらかが画面外に取り残されない）
- ダメージ補正（コンボが伸びるほど減る。下限 10%）

## 6. コンボが永久に続かないようにする（必ず入れる）

**「ヒット時硬直差 ≧ 発生フレーム」の技は、理屈のうえで自分自身に永久につながります。**
スト 6 のリュウの立ち弱パンチ（+4F / 発生 4F）もこの条件を満たします。
そして画面端では押し戻しで距離も開かないので、対策が無いと本当に永久に続きます。

次の 3 つを必ず入れてください。

### 6-1. のけぞりの減衰
コンボが伸びるほど、のけぞりが 1F ずつ短くなります。
```
減衰 = min(max(0, コンボ数 - 2), 6)
のけぞり = max(元の 60%, 元 - 減衰)
```
3 発目あたりで硬直差が発生フレームを下回り、自然にコンボが終わります。

### 6-2. 画面端の押し戻し
相手が壁に張りついていて下がれないぶんは、**殴っているほうが下がります**。
そのために、押し戻し用の速度を移動速度とは別に持ってください
（技を出している最中でも押し戻しだけを効かせるため）。

### 6-3. 打ち上げ回数の上限
空中の相手は 4 回までしか浮かせ直せません。上限に達した相手には当たらずすり抜けます。
また、回数を重ねるほど打ち上げの高さも下がります。

### 検証のしかた
**押せるボタンを総当たりで試して、いちばん長く続くコンボを機械的に探すテスト**を書いてください。
1 フレームごとに全ボタン（＋下方向）を試し、「コンボが途切れない手」を選び続けます。
画面中央と画面端の両方で、上限（例：12 発）に収まることを毎回確かめます。

> 実際にこの探索を書いたところ、対策前は打ち切りの 61 発までつながっていました。
> 手で試していたら見つかっていません。

## 7. 入力とコマンド認識

- 1 フレームぶんの入力は **16 ビットの整数 1 個**（上下左右 + 6 ボタン）
- 入力履歴は 32 フレームぶんのリングバッファ
- 入力バッファ 10 フレーム（硬直明けに技が出る猶予）
- ボタンごとに「最後に押されたフレーム」と「すでに技として使ったフレーム」を持つ

### コマンド認識

方向はテンキー表記（5 が中立、**前が 6 になるよう向きで正規化**）に直します。
コマンドは「古い順に並んだ、通ればよい方向の集合」の列として持ち、
履歴を新しいほうから古いほうへたどって順に消し込みます。

```
236    → [[2,1,3], [6,9]]
214    → [[2,3,1], [4,7]]
623    → [[6,9], [2,1], [3,6,9]]
236236 → [[2,1,3], [6,9], [2,1,3], [6,9]]
63214  → [[6,9,3], [2,3,1], [4,7]]
```

**斜めは書かないでください。**「下 → 前」のように要点だけを見て、
あいだに何が挟まっていても通します。斜めを必須にすると、
飛ばして入れたときに出なくなります。

**同じ方向を 2 つの段に登場させないでください**（後述の落とし穴 A）。

### ため技
「ためている」だけでは成立させないでください。
**ためたうえで反対方向を入れて初めて成立**とします（後述の落とし穴 B）。

## 9. CPU 対戦相手

**人間とまったく同じ入力しか行わないこと。**
体力を直接いじったり、コマンドを飛ばして技を出したりは禁止です。
波動拳を撃ちたいときは `2` `2` `3` `3` `6` `6+P` と 1 フレームずつ本当に入力します。

強さは 4 段階。**判断を間違えさせるのではなく、「見てから動くまでの時間」で弱さを作ります。**
数フレーム前の状況を見て判断させることで、人間らしい弱さになります。

| | 反応 | 攻めの頻度 | ガード | 対空 | コンボ完走 |
|---|---|---|---|---|---|
| やさしい | 26F | 28 | 30% | 12% | 20% |
| ふつう | 15F | 54 | 68% | 52% | 68% |
| つよい | 10F | 70 | 84% | 75% | 85% |
| 鬼 | 5F | 84 | 96% | 94% | 97% |

判断の順番：

1. 予約した入力が残っていれば出す（コマンド入力の途中）
2. のけぞり中 → ガードを入れ続ける
3. **ガード硬直が明ける直前 → 押し返す**（後述の落とし穴 C）
4. 起き上がり → 一定確率で無敵技
5. 相手が跳んでいる → 対空
6. 相手の攻撃が届く → ガード
7. 自分の技が当たった → 必殺技でキャンセル
8. 相手が空振って硬直している → その硬直に間に合ういちばん強い技
9. それ以外 → 作戦（近づく / 下がる / 攻める / 飛び道具）

**攻めるときは、届く技しか振らないこと。** 届かない技を振ると硬直を晒して反撃をもらいます。

ため技キャラは、その場でためはじめると 48F 棒立ちになります。
**「すでにたまっているときだけ出す」ようにし、待っているあいだは後ろを入れてためておきます。**

## 10. 描画

画像を使わず、腰・胴・頭・両腕・両脚を角度で組み立てて描きます。

```
角度は「真下を 0 度、前へ回す向きを +」で数える
  0 度 = 真下      90 度 = 前へ水平
180 度 = 真上     -90 度 = 後ろへ水平
```

技のポーズは **3 つで 1 組**（ため → 当てる → 戻す）にし、
今のフレームがどの区間かで補間します。
発生の前半はゆっくりため、後半で一気に伸ばす曲線を使うと、
同じフレーム数でも速そうに見えます。

### 棒人間に見せないための要点

- 手足は**先細りのカプセル**にする（付け根を太く、先を細く）。同じ太さの棒を並べるのが棒人間に見える一番の原因
- 手足と胴に**陰**をつける（向いている側を明るく、奥側を暗く）
- 胴は腰・胸・肩の 3 点で作り、肩幅を広く腰を細く
- 手先は前腕の向き、足先は進行方向に伸ばした楕円にする（丸い玉だと風船に見える）
- 顔に首・耳・眉・目・鼻・口を描く。**表情を状態で変える**（攻撃中は食いしばり、喰らったら目を閉じる）
- キャラごとに身につけるもの（鉢巻き・手甲・ブーツ・肩当て・前を開けた上着）を描き分ける
- 外周を一段暗く縁取る（背景に溶けないように）
- 奥側の手足は暗い色で先に描き、胴 → 頭 → 手前の手足の順に重ねる

### そのほか

- 背景は多重スクロール（奥はゆっくり、手前は速く）。ステージ 3 種以上
- ヒットエフェクト、画面揺れ、残像、超必殺技の暗転とスピード線
- 体力バーは 2 枚重ね（手前が今の体力、奥が遅れて追いつく赤いバー）
- コンボ数、ゲージ、制限時間、ラウンド取得の表示
- 当たり判定の可視化（赤＝攻撃 / 緑＝食らい / 青＝押し合い）

## 11. 音

Web Audio で合成します。ファイルは置きません。

- 打撃：短いノイズ + 低い音。弱・中・強で長さと周波数を変える
- ガード：高い金属音
- 空振り：帯域を絞ったノイズ
- 飛び道具、掛け声、ジャンプ、着地、ダッシュ、KO、超必殺技
- BGM：4 小節ループのベース + リード + ドラム。対戦用とメニュー用

## 12. 画面とモード

| モード | 内容 |
|---|---|
| アーケード | ロスター全員を順に倒す。勝ち進むほど CPU が強くなる |
| CPU と 1 戦 | 好きな相手と 1 試合 |
| 2 人対戦 | 1 台のキーボードで対戦 |
| トレーニング | 相手の行動固定、自動回復、判定表示、フレーム表示、入力表示 |
| オンライン対戦 | ロールバック方式 |
| 技表 | 全キャラの全技のフレームデータ（データから直接読む） |
| 操作説明 / 設定 | 難易度・ラウンド数・制限時間・音量・判定表示 |

- タイトル画面では**裏で CPU 同士に実際に戦わせる**（アーケードのデモ画面）
- トレーニングの「ガード」は後ろを入れっぱなしにするのではなく、
  **攻撃が当たる瞬間だけ**ガードを入力する（空振りにはガードしないので、間合いの確認にそのまま使える）

### 操作

| | キー |
|---|---|
| 1P | WASD 移動、U/I/O パンチ、J/K/L キック |
| 2P | 矢印キー、テンキー 4/5/6・1/2/3（無い環境用に Z/X/C・V/B/N も） |
| 投げ | 弱P + 弱K |

**1P と 2P でキーが重ならないことをテストで担保してください**（後述の落とし穴 D）。

## 13. オンライン対戦（ロールバック）

1. 毎フレーム、進める直前の状態をまるごと控える
2. 相手の入力が来ていないフレームは「直前に確定している入力と同じ」と決めつけて進める
3. あとで本当の入力が届いて予想と違っていたら、そのフレームまで巻き戻し、
   正しい入力で今のフレームまで一気にやり直す

接続はサーバを使わない WebRTC の直接接続（招待コードを手で 2 回やり取りする）。

**検証**：わざと入力を遅らせて流し、
**「遅延ありでロールバックした結果」と「最初から全入力が分かっていた場合」の状態が
完全に一致すること**をテストで確かめてください。一致しなければ決定論が壊れています。

---

## 14. 受け入れ条件（テストで担保すること）

1. **フレームデータの実測**：データに書いた硬直差と、実際に試合を回して測った硬直差が 1F も違わない
2. **無限コンボが無い**：総当たり探索で、画面中央でも画面端でも上限内に収まる
3. **コマンドの暴発が無い**：236 を押しっぱなし気味に入れても 236236 にならない／ためているだけでため技が出ない
4. **決定性**：同じ入力からは必ず同じ状態になる。座標がすべて整数のまま
5. **ロールバック**：遅延ありの結果が、遅延なしの結果と完全に一致する
6. **CPU の強さが段階になっている**：鬼 > つよい > ふつう > やさしい を数十試合回して確認
7. **CPU が連打相手に勝てる**：「近づいて中攻撃を連打するだけ」の相手に、鬼は 10 戦 8 勝以上。
   ただし**やさしいは勝ちすぎない**（初心者が勝てる余地を残す）
8. **キャラの釣り合い**：同キャラ対戦が一方的にならない。どのキャラも他キャラ相手に勝てる
9. **キー配置**：1P と 2P でキーが重ならない
10. **画面端**：壁を越えない。2 人が離れすぎない。重なったままにならない

## 15. 実装順序（この順で作ると詰まりにくい）

1. 定数・型・入力（決定論の土台）
2. ファイターの状態と当たり判定
3. 試合の 1 フレーム更新（ここが中心）
4. **フレームデータの実測テスト** ← 描画より先に書く
5. キャラクターと技のデータ
6. 描画（ポーズ → 骨格 → エフェクト → 背景 → HUD）
7. 画面遷移とメインループ
8. CPU
9. 無限コンボの探索テスト
10. オンライン対戦

**4 を描画より先に書いてください。** 目で見て調整すると、
必ずどこかで「表の数字と挙動が違う」状態になり、あとから直すのが非常に高くつきます。

## 16. 落とし穴集（実際に踏んだもの）

### A. 236 のつもりが超必殺技（236236）が暴発する

コマンド認識で、同じ方向が続いているのを別々の入力として数えると起きます。
実際に遊ぶと斜めは必ず数フレーム押しっぱなしになるので、
`2` `3` `3` `6` `6` の `3` が 2 回ぶんに数えられ、236236 が成立してしまいます。

**対策**：ある段が成立したら、**同じ方向が続いている間はまとめて読み飛ばす**。
さらに、同じ方向を 2 つの段に登場させない（`236` の最後の段に `3` を入れない）。

### B. ガードしているだけでため技が暴発する

「ためている」だけで成立にすると、後ろを入れてガードしているだけで技が出ます。
**ためたうえで、直近数フレーム以内に反対方向が入っていること**を条件にしてください。

### C. スト 6 のフレームだと、CPU がガードするだけでは何もできない

弱攻撃が -1F、中攻撃が -3F といった数値なので、ガードしても確定反撃が取れません。
ガードを固めるだけの CPU は、近づいてボタンを押すだけの相手に一方的に負けます。

**対策**：**ガード硬直が明ける瞬間に押し返す**判断を入れてください。
相手の硬直に間に合う技があればそれを、無ければいちばん速い技を置きます。
これを入れる前と後で、連打相手への勝率が 3/10 → 10/10 に変わりました。

### D. 1 台のキーボードで 2 人対戦するとき、キーが重なる

2P の予備キーを適当に割り当てると 1P と衝突します。
片方を操作するともう片方も動くのですが、**対戦中は「なぜか相手が勝手に技を出す」
という形でしか出てこない**ので、非常に気づきにくいです。テストで塞いでください。

### E. 押してすぐ離したキーが 1 フレームも入力されない

画面の更新は 1/60 秒ごとですが、キーを押している時間はそれより短いことがあります。
`keydown` / `keyup` を単純に集合で持つと、フレームの合間に押して離した入力が消えます。

**対策**：押した記録を別に持ち、離したあとでもそのフレームは「押されている」として扱う。

### F. 決着したのに相手が立ったまま終わる

倒しきった一撃の吹き飛びを技の性質任せにすると、
軽い技で倒したときに立ったまま体力 0 になって終わります。
**倒しきった一撃は、技によらず必ず吹き飛ばしてください。**

### G. 画面端でキャラクターが見切れる

カメラをステージ端でぴったり止めると、端に押し込まれた側の腕や脚が画面外に出ます。
**壁の外を少し（20px 程度）見せる余白**を持たせてください。

### H. スローモーション演出でフレーム番号を進めてしまう

決着後のスロー再生で「シミュレーションを進めずにフレーム番号だけ足す」実装をすると、
ロールバックやイベントの重複判定が壊れます。**進めない**だけにしてください。

### I. 演出が二重に出る

ロールバックで同じフレームをやり直すと、火花や音がもう一度出ます。
描画側で「すでに見たフレーム番号以下は無視する」ようにしてください。
